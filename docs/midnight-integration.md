# Midnight Chain & Wallet Integration

This document explains how Shadow Cipher interacts with the **Midnight**
blockchain and crypto wallets. The core idea: the secret code is committed
on-chain at game creation, and a winning guess is verified against that
commitment with a **zero-knowledge proof** — proving you cracked the code
without the code ever being revealed on-chain or sent to your browser.

For the gameplay rules, see [gameplay.md](./gameplay.md).

## Wallets

The game connects to Midnight-compatible browser wallet extensions:

- **Lace** (`lace` / `LACE`)
- **1AM** (`1am` / `midnight-1am-wallet` / `1AM`)

The connect dialog is **locked to mainnet only** — the network is a hardcoded
`MAINNET` badge, not a selectable dropdown.

Connection logic lives in
`frontend-vite-react/src/modules/midnight/wallet-widget/api/walletController.ts`:

1. Discover the wallet API via `window.midnight[key]` (or by matching
   `api.name` / `api.rdns`, including Lace's UUID key).
2. Call `initialAPI.connect(networkID)` → returns a `ConnectedAPI`.
3. Persist `rdns-connected` and `network-id` to `localStorage`; auto-reconnect
   on mount.
4. Query balances/addresses via `getDustBalance()`, `getDustAddress()`,
   `getShieldedAddresses()`, `getUnshieldedAddress()`, `getUnshieldedBalances()`.

## The Smart Contract

The on-chain logic is written in Midnight's **Compact** language at
`shadowcipher-contract/src/shadowcipher.compact`.

### Ledger (public) state

- `next_game_id: Counter` — auto-incrementing game ID.
- `games: Map<Uint<64>, Game>` — maps a game ID to `{ commitment: Bytes<32>,
  active: Boolean }`.

The `commitment` is a hash of the secret code plus a salt. It's public but
reveals nothing about the code.

### Private state (witnesses)

Defined in `shadowcipher-contract/src/witnesses.ts` as
`ShadowCipherPrivateState`:

- `code: [number, number, number, number]` — the 4-color secret (values 0–5)
- `salt: Uint8Array` — 32 random bytes, fresh per game

These never leave the server / proof generation; they're fed into the circuits
as private witnesses only.

### Circuits

| Circuit | Purpose |
|---|---|
| `create_game()` | Computes `commitment = persistentHash(GameSecret { code, salt })`, increments `next_game_id`, stores the game, and returns the new `game_id`. |
| `submit_guess(game_id, g0, g1, g2, g3)` | Recomputes the hash from the private witnesses, asserts it matches the stored commitment, checks whether the guess equals the secret, marks the game inactive if correct, and discloses the boolean result. |
| `delete_game(game_id)` | Reclaims storage for an inactive game (requires knowing the secret + salt). |

This commitment-then-reveal pattern is what makes the game trustworthy: the code
is locked in at creation, and the proof guarantees a winning guess truly matches
that committed code.

## On-Chain Game Lifecycle

The server (`server/src/`) sponsors all on-chain interactions, so players need
no funds.

1. **Pre-generation (pool).** A background `poolWorker.ts` keeps a pool of
   ready-to-play games (target `POOL_TARGET_SIZE`, default 20; refill every
   ~10s). Each runs `createOnChainGame()` (`server/src/api.ts`) and stores
   `game_id`, `code`, `salt`, and `contract_addr` in SQLite. Refill **pauses
   while players are in active sessions** to keep the DUST coin free.
2. **Session start** (`POST /api/session/start`). Claims a pooled game FIFO, or
   creates one on demand, or falls back to demo mode. Returns `sessionId`,
   `contractAddress`, `gameId`.
3. **Guesses** (`POST /api/guess`). Answered **off-chain** by the server
   (`calculatePegs`) — no transaction. Capped at 10 attempts per session.
4. **Declare / final** (`POST /api/declare`). Runs `submitGuessOnChain()` which
   calls the `submit_guess` circuit, signs and submits the transaction, and
   returns `{ correct, txId }`. Also records the score.

The secret code is held server-side in the session row and is **never sent to
the client**.

## DUST Coin & Transaction Fees

Midnight transaction fees are paid in **DUST** (distinct from NIGHT).

- The server wallet holds DUST to **sponsor** player transactions — the game
  pays all fees.
- DUST is generated from NIGHT UTXOs: fund the server's unshielded address with
  NIGHT, then `registerNightUtxosForDustGeneration()` lets the network accrue
  DUST. (`server/src/api.ts`)
- `GET /api/dust` reports `{ available, pending, availableCoins, pendingCoins }`.

### Single-coin queueing

The server typically holds a **single DUST coin**, so transactions must be
serialized. `server/src/onChainQueue.ts` is a priority semaphore:

- `enqueueOnChain(fn)` — high priority, player-facing guesses/declares.
- `enqueuePoolRefill(fn)` — low priority, background pool generation.

This is why pool refill yields to active players.

## Proofs

- Zero-knowledge proofs are generated by a **proof server** (`PROOF_SERVER_URL`,
  default `http://127.0.0.1:6300`).
- The frontend build copies compiled ZK artifacts (keys, ZK IR) from the
  contract's `managed/shadowcipher/` into `public/midnight/shadowcipher/`.

## Frontend Stack

`frontend-vite-react/` — **Vite 7 + React 19**, TanStack Router, Radix UI,
Tailwind CSS 4. The game UI is a canvas-based terminal/arcade renderer in
`src/pages/shadowcipher/index.tsx`, talking to the sponsor server via
`src/lib/sponsorApi.ts` (`startGame`, `submitGuess`, `declareAnswer`,
`getStatus`, `getPoolInfo`). In dev, Vite proxies `/api` → `http://localhost:3003`.

## Data Storage

State is stored in **SQLite** (`server/src/kvStore.ts`):

- `sessions` — secret `code`, `salt`, `game_id`, `contract_addr`, `guesses`,
  expiry (1-hour TTL, swept every 10 min). Secret never leaves the server.
- `pool` — pre-generated on-chain games.
- `players` — `best_score`, `games_played`, `games_won`, mode.

Secret codes and salts are generated with Node's CSPRNG (`crypto.randomInt`,
`crypto.randomBytes`), not `Math.random`.

## API Endpoints (Sponsor Server)

| Endpoint | Purpose |
|---|---|
| `POST /api/session/start` | Start a game (on-chain or demo). |
| `POST /api/guess` | Submit a guess; returns black/white pegs (off-chain). |
| `POST /api/declare` | Final guess + ZK proof + score record. |
| `POST /sponsor` | Balance, sign, and submit a client transaction with DUST. |
| `GET /api/status` | Proof server / node / indexer / pool / contract health. |
| `GET /api/pool` | `{ size, target }`. |
| `GET /api/dust` | DUST balance details. |
| `POST /api/session/name` | Attach a display name to a finished session's leaderboard row (rename only). |
| `POST /api/metrics/scores` | Compatibility endpoint — returns `{ recorded, player }` with the player's already-recorded figures (`recorded: false, player: null` if none). Does **not** write submitted results; `/api/declare` is the only path that records a score. |
| `GET /api/metrics/leaderboard` | Top players. |
| `GET /api/achievements/public/list` | Achievements + completion %. |
